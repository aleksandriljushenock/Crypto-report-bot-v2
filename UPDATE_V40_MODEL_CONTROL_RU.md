# V40 — Model Control Center

V40 добавляет управление self-learning/AI моделью прямо из Telegram.

## Как открыть

- AI Центр → `🧠 Управление нейромоделью`
- или команда `/model`
- версия бота: `/version`

## Runtime-настройки

Настройки сохраняются в `data/learning_v14.db` и переживают перезапуск контейнера. `.env` используется как fallback, если конкретный runtime-параметр ещё не менялся из Telegram.

### Minimum samples
Минимум завершённых observations перед полноценным обучением. Больше — стабильнее и медленнее; меньше — быстрее адаптация, но выше риск переобучения.

### Specialist minimum samples
Сколько собственных observations нужно для regime/LONG/SHORT specialist. Большое значение делает специалистов статистически устойчивее; маленькое быстрее создаёт узкие модели, но повышает шум.

### Walk-Forward folds
Количество последовательных временных validation-окон. Больше folds усиливает проверку устойчивости между периодами рынка, но требует больше данных.

### Search iterations
Количество вариантов весов, которые проверяет optimizer. Больше — глубже поиск и выше CPU cost; слишком большой поиск на маленькой выборке увеличивает риск переоптимизации.

### Max weight change
Максимальная свобода изменения веса относительно базового значения. Большое значение ускоряет перестройку модели, маленькое удерживает модель близко к исходной логике.

### Minimum utility gain
Какое минимальное преимущество challenger должен показать над champion. Больше — реже promotion и выше стабильность; меньше — быстрее переключение моделей.

### Recency half-life
Скорость уменьшения веса старых observations. Большое значение дольше хранит память рынка; маленькое сильнее ориентирует обучение на свежие сделки.

### Learning Rule minimum samples
Сколько подтверждений нужно автоматическому learning rule. Большое значение уменьшает число случайных правил, маленькое быстрее создаёт новые правила.

### Max Rule Adjustment
Максимальная суммарная поправка к AI Score от learned rules. Большое значение позволяет правилам сильнее менять ranking; маленькое оставляет базовые факторы доминирующими.

### Minimum Holdout Samples
Минимальный размер финального участка данных, который optimizer не видел. Это один из главных safety-параметров promotion.

## Профили

### Safe
Консервативное обучение: больше данных, меньше свободы весов, более строгий holdout. Для стабильной длительной работы.

### Balanced
Основной рекомендуемый профиль. Баланс адаптации и защиты от overfitting.

### Aggressive
Быстрая адаптация: меньше samples до обучения, больше search iterations и свободы весов. Выше риск переобучения.

### Custom
Включается автоматически после ручной правки параметра.

## Веса факторов

Для каждого AI-фактора доступны три режима:

- `AUTO` — использовать вес Champion без ручного ограничения.
- `BOUNDED` — разрешить модели обучаться, но удерживать вес внутри заданного коридора от base weight.
- `MANUAL` — зафиксировать base weight и не позволять обучению менять итоговый вес этого фактора.

Управляются Trend, Momentum, Volume, Funding, Open Interest, Timeframe Alignment, Risk/Reward, Capital Flow, Narrative, News Sentiment и Smart Money.

`BOUNDED` является рекомендуемым ручным режимом: он позволяет сохранить learning, но не даёт одному фактору стать чрезмерно доминирующим.

## Champion / Challenger

Панель показывает последние локальные версии и позволяет вручную активировать сохранённую версию. Это осознанный rollback/promotion и он обходит автоматическое решение safety-gates, поэтому использовать ручную активацию стоит только при понятной причине.

## Автообучение

Переключатель `Автообучение ВКЛ/ВЫКЛ` останавливает именно автоматический training cycle. Сбор outcomes и работа текущего Champion продолжаются. Ручное `Обучить сейчас` остаётся доступным.

Одновременно может идти только одно обучение внутри процесса: V40 добавляет training lock между ручным и фоновым запуском.

## Хранение

Новые таблицы создаются автоматически в существующем SQLite `learning_v14.db`:

- `model_runtime_settings`
- `model_weight_controls`
- `model_control_audit`

Отдельная Supabase migration для V40 не требуется.
