# Scanner Coverage & Unified Status v20

## Что исправлено

Раньше было два разных признака занятости: Telegram следил только за ручным `trade_scan_thread`, а торговый движок имел отдельный `_SCAN_LOCK`. Поэтому фоновый монитор мог реально сканировать рынок, а кнопка «Статус скана» показывала «Сканер готов».

В v20 статус берётся из единого engine lock/state. Видно источник (ручной/монитор), этап и прогресс `N/Total`. Ручной скан не создаёт лишний поток, если фоновый проход уже идёт.

## Увеличение охвата без роста RAM пропорционально числу монет

Скан теперь обрабатывает universe batch-ами. Сырые свечи хранятся только для небольшого batch и освобождаются после анализа. Это позволяет поднять `TRADE_TOP_LIQUID_SYMBOLS` без прежнего скачка RAM.

Рекомендуемые Railway значения для 1 GB RAM:

```env
TRADE_TOP_LIQUID_SYMBOLS=50
TRADE_SCAN_BATCH_SIZE=8
TRADE_SCAN_MAX_WORKERS=2
HEDGE_CANDIDATE_POOL=16
MULTI_EXCHANGE_MIN_VENUES=1
MULTI_EXCHANGE_MIN_QUOTE_VOLUME_USDT=30000000
```

Если RAM стабильно ниже ~750 MB, можно проверить 60, затем 75 монет. Лучше увеличивать universe, а не резко повышать workers.

`MULTI_EXCHANGE_MIN_QUOTE_VOLUME_USDT` снижен в рекомендации с 50M до 30M, чтобы добавить ликвидные mid-cap инструменты. Код не перезаписывает текущую Railway переменную автоматически.
